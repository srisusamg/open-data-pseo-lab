Data Rankings Frontier Methods

Transparent by design

Methodology

Canonical facts come only from cited, validated source records. No AI-generated inference becomes canonical data.

Hybrid research data

Data sources and methodology

The published dataset merges separately stored automated observations and human-curated research into one canonical field-level record. Rankings, insights, comparisons, and pages consume only that merged record.

Automated and human-curated facts

Automated facts are extracted from structured catalog and provider observations. Curated facts live in a human-editable CSV and are never changed by automation. Each fact carries its external source, URL, observation date, confidence, and verification status. The website names that external source rather than displaying “human curated” as the source.

Precedence and conflicts

A fresh, verified human fact marked preferred is selected over automated data. A locked human fact always remains canonical until a curator changes or removes the lock. Otherwise trusted automated data is selected. Both records are preserved when values differ, and the deterministic conflict report records the selected value and reason.

Freshness, coverage, and missing data

Category-specific policy classifies facts as FRESH, AGING, or STALE; stale facts are retained, never deleted. Coverage and the prioritized P0/P1/P2 research queue expose absent and stale fields. Missing facts display as unavailable and are never converted to zero.

Derived metrics and ranking eligibility

Derived costs and value measures run after canonical selection. A ranking accepts only the facts required by its formula, with compatible units, complete provenance, and freshness within the configured limit. Models that fail those gates are excluded rather than assigned a zero.

Catalog taxonomy

Models may be API, hosted, open-weight, local, product-only, or preview distributions, and may have more than one distribution. Availability and capability fields can remain unknown when an official source does not establish them. Open-model parameter, architecture, quantization, and hardware fields are optional; hardware is never estimated.

Pricing normalization

Pricing is optional. Source prices are accepted only in explicit USD-per-token, USD-per-1,000-token, or USD-per-1,000,000-token units, then normalized to USD per 1M tokens. Cached input is retained separately when published. Models without comparable public API input and output pricing are shown in the catalog and excluded from price rankings.

Workload profiles

Profiles are explicit examples, not universal defaults. For each profile, blended cost is input price × input tokens / 1M + output price × output tokens / 1M.

Value metrics

intelligence-per-dollar-v2 calculates intelligence per input dollar, intelligence per output dollar, blended workload cost, intelligence per blended dollar, and—only when comparable throughput exists—speed-adjusted value. Included benchmark IDs: aa-intelligence-index-v4.1. Every result retains its benchmark, version, harness, comparison group, workload, and formula version.

Benchmark groups and composites

Observations are grouped as general intelligence, reasoning, coding, or multimodal. Rankings stay inside the same benchmark version, unit, evaluation configuration, and comparison group. Unrelated scores are never blindly averaged. This release defines no site-created composite. Any future composite must declare its benchmark IDs, weights, normalization, and version so it can be reproduced.

Pareto frontier

The price-performance frontier is calculated per comparable benchmark cohort and workload. A model is dominated only when another model performs at least as well and costs no more, with at least one strict advantage.

Publication and ranking gates

A model page needs canonical identity, provider, useful taxonomy and availability metadata, complete dated provenance, deterministic insight evidence, a valid canonical URL, and internal links. Missing values are never treated as zero. Price and value rankings reject pricing older than 120 days; benchmark rankings reject observations older than 365 days; latency and throughput reject observations older than 120 days. Every shown observation includes its age.
